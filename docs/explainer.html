How to use this document

If you are new to web development, read straight through. Part II defines every term before it is used. If you are an experienced engineer, skim Part I, jump to Part III for the architecture, Part VI for the interesting algorithms, and Part V when you need to find a file.

Part I. The project in plain English

One sentence: this is a personal portfolio website that looks and behaves like a Windows 95 computer, with working programs instead of web pages.

An analogy: most portfolios are a brochure. This one is an office you walk into. The resume is a document open on the desk. The projects play on a television in the corner. The mail is in the mail program. You do not scroll; you double-click.

The problem it solves: a portfolio has one job, to be remembered. Every scrolling single-page portfolio looks like every other. A desktop you can actually use is remembered.

What it does: boots to a teal desktop with draggable icons, a Start menu, a taskbar with a live clock and volume control, and windows that open, move, resize, minimise and maximise. Inside those windows: a resume in a recreated Microsoft Word, an About page styled as a 2005 profile site, a projects page styled as 2005 YouTube, mail in a recreated Outlook Express with 68 messages across its folders, a photo gallery, a guestbook backed by Postgres, MS Paint, Notepad, an MS-DOS prompt, a calculator, a file explorer, a recycle bin, Internet Explorer serving the 1996 web through the Internet Archive, a real Winamp, CD Player, Phone Dialer, ScanDisk, Disk Defragmenter, and eight playable games. Around them: wallpaper and resolution switching that actually apply, a sound scheme, Clippy, a shutdown sequence, and one secret behind a famous ten-key code.

What it does not do: it persists only what you opt into on the welcome dialog, plus the guestbook, the colour scheme and the resolution; wallpaper reverts to the teal default on refresh by design. It does not run real DOS software. Its Internet Explorer cannot load external websites. It is not a Windows emulator; every program is a purpose-built recreation.

Part II. Background concepts

Web page and browser
A browser downloads documents written in HTML, styles them with CSS and runs JavaScript to make them interactive. This whole project is one page whose JavaScript redraws everything.
React
A JavaScript library for building interfaces out of components. A component is a function that returns markup and re-runs when its data changes. Every window, icon and menu here is a component.
Next.js
A framework around React that handles routing, building and server code. This project uses one route, the desktop, plus server actions for the two forms.
Server action
A Next.js function that runs on the server but is called like a local function from the page. The contact form and guestbook write through server actions, which is what keeps secrets off the client.
TypeScript
JavaScript with type annotations, checked before the code runs.
Tailwind CSS
A styling system of small utility classes composed in markup, used for almost all styling here alongside a hand-written globals.css.
Canvas
A drawing surface the page paints pixel by pixel from JavaScript. Pong, Paint and the Solitaire win animation draw on canvases.
Web Audio API
The browser's sound synthesiser. Nearly every sound here is generated from oscillators at play time rather than loaded: the system scheme, the game effects and the creature cries are all synthesised. The exceptions are files the owner supplies, which the repository carries as named slots: the battle and victory themes, the chess move recordings, and fifteen silent placeholders Winamp lists by name until real recordings replace them.
localStorage
A small key-value store the browser keeps per site. The colour scheme and resolution choices live there; wallpaper deliberately does not, so it reverts on refresh.
Postgres
A relational database. The guestbook keeps its entries in one, reached through a pooled connection string in an environment variable.
Windows 95
Microsoft's 1995 operating system: the teal desktop, the grey bevelled windows, the Start button. The visual grammar this project recreates: raised edges are light-top-left dark-bottom-right, pressed edges are the reverse, and the system palette leans on #c0c0c0 grey, #000080 navy and #008080 teal.

Part III. System architecture

Browser
└── app/page.tsx            one route, owns the window list
    ├── BootSequence        shown once, then never again
    ├── Desktop             icons, wallpaper, selection marquee, context menus
    │     └── DesktopItem   one icon: drag, rename, open
    ├── Window (per open id)
    │     └── window-content/*   the program inside the frame
    ├── Taskbar             Start button, running windows, tray, clock
    ├── StartMenu           cascades: Programs, Accessories, Documents...
    ├── Clippy              watches the active window
    ├── Winamp              webamp, loaded only when opened
    ├── Shutdown, RunDialog, MessageBoxHost, PokemonBattle
    └── window-titles / sound / resolution   shared lib

Server (only two paths leave the page)
├── actions/send-email.ts   contact form screening; the browser delivers
└── actions/guestbook.ts    guestbook -> Postgres via DATABASE_URL

Principles. One page owns the truth: app/page.tsx keeps the list of open, minimised and focused windows and passes callbacks down. Windows talk back through DOM custom events (openWindow, windowAction, openRun, openShutdown) so any component can open any program without prop drilling. Everything visual is drawn, not shipped: icons are pixel-grid SVG or generated PNG, sounds are synthesised, the one exception being photographs and the licensed critter sprites. Server code exists only where a secret or shared state demands it.

Runtime paths that differ. On screens narrower than 768px windows open maximised and lose the maximise control. With DATABASE_URL unset the guestbook falls back to an in-process list and says so. With prefers-reduced-motion set, animations are suppressed.

Part IV. How the project was built

The commit history tells the story in eras, which the desktop's own Release Notes window (Start, Documents, Release Notes) retells. The idea was born at a 24-hour hackathon in December 2024, which produced the base layer and ran out of clock. First boot in July 2025: desktop, windows, the core programs. A resume content pass in February 2026. Then, in August 2026, a long series of authenticity and depth passes: the games grew from five to eight, the guestbook moved onto Postgres, the shell gained Run, Date/Time, Properties, sounds, Clippy, Winamp, Internet Explorer, a working Display Properties, and a phone layout. Screensavers came and later went again by the owner's choice. A final pass in mid August made the shell honest in the small places: Find searches the virtual drive, the Sounds applet plays the real scheme, File and Print in Word produces the actual resume, saved files and Paint drawings persist between visits, and the desktop drives from the keyboard with an Alt+Q window switcher. A polish pass followed: the Appearance tab gained schemes that truly recolor the shell, the wallpaper set became drawn imitations of what the box shipped, the tray monitor grew a QuickRes menu, and two hit counters in the guestbook's database gave Clippy and the 1996 home page one real number each. The last strokes: Word saves as Word and PDF, Winamp takes the visitor's own files, the drive's Readme became the guide to the hidden features, and the start menu banner and desktop context menu took their reference look from the Yuteoctober recreation. The plan was never written down in advance; the constant was a rule of thumb, that anything on screen should behave the way 1995 did, and where the original was worse than useless (an unwinnable Pong bot, a title bar inside a title bar) the fix follows what Windows would have done.

Part VI. Core logic in depth

Window management

app/page.tsx holds openWindows, minimizedWindows and activeWindow. Focus raises z-index from 100 to 200. Each app has a default and minimum size table in window.tsx; Calculator resizes its own window when switching Standard and Scientific by dispatching windowAction {action:"resize"}, and is in the NEVER_MAXIMIZE set because the real one had no maximise button.

The games' options

Every game now carries its own sound switch in its menus. Solitaire scores Standard (with the original's 700000 divided by seconds time bonus) or Vegas ($52 buy-in, $5 a card, shown in dollars), draws one or three, offers twelve card backs, and wins instantly on Alt+Shift+2. Minesweeper has the Custom Field dialog with the original's clamps, the Fastest Mine Sweepers table with Reset Scores, the xyzzy corner pixel, and a Flowers skin. FreeCell tracks wins, losses and streaks in a Statistics dialog, and answers Select Game with -1 or -2 by dealing the deck unshuffled, aces buried, in the spirit of the original's prank deals. Hearts asks your name once, points an arrow on the pass button, keeps a per-hand score sheet, and raises a moon for whoever shoots it. Pong seats a second player on W and S.

The FreeCell deal

Deals are numbered like the original because they use Microsoft's actual generator, a linear congruential generator: seed = seed * 214013 + 2531011, take (seed >> 16) & 0x7fff, swap cards down the deck. Deal 11982 is still unwinnable.

The Pong opponent

The bot re-reads the ball on a delay rather than tracking continuously, and its read lands off-centre by a per-difficulty error: Easy is 130 px/s of paddle speed, a 0.42 s stale read and up to 42 px of error; Medium 195, 0.22, 20; Hard 300, 0.09, 5. When the ball moves away it drifts to centre, which opens angles. This replaced a bot that could reach every ball, verified by a test that tracks the ball and must score on Easy inside a minute.

Chess

Easy plays a random legal move. Medium scores every legal move by material and takes the best. Hard subtracts the opponent's best reply, one ply of lookahead.

The sound synthesiser

lib/sound.ts builds every effect from oscillator primitives: tone, sequence, noise and knock (the chess set models the modern chess.com shape, one wooden impact with layers). Message box sounds follow the icon: information dings, errors get the four-note falling chord. The startup chime arms itself on the first user gesture because browsers refuse audio before one.

ADVENTURE.EXE

lib/adventure.ts is a pure state machine: newGame() returns a state, advance(state, line) returns the next state and the lines to print, and the DOS window owns nothing but the state object. Fourteen rooms across a 1995 office, a two-word parser (USE A ON B, GIVE A TO B), and four locks in a chain: a dark basement wants the flashlight, the stairwell wants the keycard a sleeping programmer trades for brewed coffee, the manager's office wants the basement's brass key, and the server room keypad wants 0x1995, read off the glowing register in the QA lab. Feeding the source disk to the build machine yields the gold master; feeding that to the duplicator in shipping wins. Purity is what lets tests/checks/adventure.js play the whole game through the terminal.

The Explorer clipboard

Copy and Cut only remember a path; the work happens at Paste, which deep-copies the node so pasting twice cannot alias one object into two folders. A name already in use takes the original's naming: "Copy of Thing.txt", then "Copy (2) of Thing.txt", extension untouched, compared case-insensitively because the drive is. A folder cannot be pasted into itself or its own descendant, which isInside decides.

The blanket font rule, and what has to escape it

globals.css carries * { font-family: ... !important } so every window inherits the system face without each one asking for it. An important declaration in a stylesheet outranks an ordinary inline style, which is a trap for anything that sets a font from JavaScript: the recreated Word set a family the page then ignored, so its font and size pickers looked broken while behaving exactly as written. Three things escape the rule, each deliberately. The MS-DOS prompt and Notepad take .win95-mono, which wins by coming later at equal specificity. The resume marks its own declarations important, because inline-important is the one thing that outranks stylesheet-important, and reasserts them after every formatting command since execCommand keeps producing fresh elements. The taskbar menu takes its own rule for the same reason.

Who owns the title bar

Most windows take the header window.tsx draws, and that header carries the drag handler. The resume does not: it is Microsoft Word, and Word's title bar is part of Word, so window.tsx deliberately skips its own. That left the resume with no drag handler at all, and the window could not be moved. Content that draws its own bar now marks it data-window-drag; the window listens for a mousedown inside any such element and starts the same drag, excluding buttons so minimise and close still just press. Double-click on the same element maximises, as it does on the standard header.

Guestbook moderation

The guestbook shows writing from strangers, so the owner can take an entry down. There are no accounts and exactly one moderator, so the control is a shared secret: GUESTBOOK_ADMIN_KEY, read on the server and never sent to the browser. The window asks for it, the server compares it with timingSafeEqual over equal-width padded buffers (a plain === leaks the matching prefix through how long it takes to fail), and every delete carries the key to be checked again, so the client holds a convenience rather than an authorisation. Wrong guesses are rate limited to five per ten minutes per address. With the variable unset there is no moderation at all and the button is not drawn.

Persistence

The virtual drive in lib/filesystem.ts hydrates from localStorage on first read and writes itself back on every mutation, under a version-salted key (win95:fs:v2) so a change to the shipped default tree can discard stale snapshots by bumping the version. Desktop items a visitor creates persist with their positions under win95:desktop-items:v1; the default icons deliberately reset to the grid on every load so a dragged icon cannot be lost. Paint's Save to Desktop turns the canvas into a data URL that is both the icon's image and its stored content. All storage access is wrapped: quota errors and disabled storage degrade to a fresh drive per visit rather than a crash. The whole mechanism sits behind a switch the welcome dialog offers on every boot (win95:persist, off until the visitor opts in): unchecking it stops new writes and clears the saved work, while display settings, high scores and the visitor number stay outside the switch as preferences rather than work.

The keyboard desktop

Icons are tabbable; focus selects, Enter or Space opens. Arrow movement is spatial rather than index-based because icons sit at free coordinates: the candidate with the least forward distance plus three times the off-axis drift wins. The window switcher lives on Alt+Q because the operating system consumes Alt+Tab before the browser sees it, the same reason Run is Ctrl+Alt+R. Q steps while Alt is held, releasing Alt commits through the same path as opening a window, which is what restores a minimised one.

Appearance schemes

The chrome is built from two Tailwind arbitrary-value classes: silver faces and navy title bars. Rather than rewrite four hundred call sites, globals.css re-declares those two generated classes after the utilities layer, routed through CSS variables that lib/color-schemes.ts writes; the fallbacks are the Windows Standard values, so a machine that never touches the Appearance tab is pixel-identical to the hard-coded original. Each scheme names a desktop, face and titlebar color, and selection highlights follow the titlebar, the way the stock schemes tied them. The wallpaper and scheme tables live in lib/ because Display Properties and the desktop's boot restore each used to carry private copies that drifted.

The resolution simulation

Choosing 640x480 sets a CSS zoom of innerWidth / 640 on the shell root. The zoom runs in both directions: the classic modes enlarge, and the 2560x1440 and 3840x2160 modes shrink the shell below 1x for more desktop area, which is what more pixels bought. The tray monitor pops a QuickRes-style menu of the six modes; the Settings tab offers the same list, because discrete modes deserve rows rather than a slider.

The battle engine

Damage is power x level / 40 scaled by the attacker's and defender's stat stages (Gen I arithmetic: stage s multiplies by (2+s)/2 above zero and 2/(2-s) below) and by the type chart: four types in one ring, CODE beats DATA beats METAL beats CHAOS beats CODE, 2x with the ring and 0.5x against it. Every move carries an accuracy score rolled per use; status moves move a stage instead of dealing damage and fail at the +-6 caps. A faint opens the party screen as a forced, penalty-free pick. All turn logic reads state through refs rather than closures, because the timer chains that pace the messages otherwise read stale team arrays, which once re-sent a fainted fighter.

The computed back sprite

The player's fighter is shown from behind, as Red and Blue drew it. Rather than hand-drawing twelve back views, backView derives one: mirror the stance, keep the ink outline, flatten highlights and dark face marks into the mid shades, and skin over the unpainted holes that eyes and mouths are made of, found by flood-filling the true outside of the silhouette. At Game Boy resolution the result is what a back sprite amounted to.

Paint's image transforms

Flip, mirror and the three rotations all take one path: the bitmap is drawn into a scratch canvas under the appropriate matrix and copied back, so the six cannot drift apart. A quarter turn keeps the canvas its own size and lands the result centred rather than resizing the drawing area mid-session. Stretch and Skew reads percentages and degrees as the original dialog did, and converts the degrees to the shear factor a matrix wants with a tangent. Cut and Copy lift the selection, or the whole bitmap when nothing is selected; Paste drops at the top left and leaves the pixels selected so they can be dragged. Set As Wallpaper writes the drawing into the same slot Display Properties fills from an upload.

The 28-colour palette

Paint's colour box is exactly MS Paint's 28, stored as fourteen dark-light pairs, and the drawn battle uses the four Game Boy tones with sprites from a CC0 set fitted to a 28x28 grid.

Part IX. Security and governance

Secrets live in environment variables, documented in .env.example, never in the repository. GUESTBOOK_ADMIN_KEY is the moderator secret: it is read in a server action only, compared in constant time, rate limited, and never included in anything sent to the browser. The two write paths are server actions: the contact form validates with zod, carries a honeypot field and an in-memory rate limit (lib/rate-limit.ts); the guestbook caps lengths and rate limits by IP. The Postgres client uses a pooled connection string. next.config.mjs sets a content security policy. The public/images/win95/NOTICE.md file records icon provenance, and the battle sprites are CC0 with the source linked in pokemon-roster.ts. Both database tables enable row level security at creation: the app's role owns them and owners bypass RLS, so the server actions are unaffected, while any other role reads nothing by default. The rate limiter logs one structured warn per rejection, so the host's log stream shows a flood as a spike of rate_limit_exceeded lines. There are no API routes, admin surfaces, or protected routes; error paths return generic messages and log details server-side only. A full-surface console sweep, part of the behaviour checks, opens every window, game, dialog and shell surface under a console listener and passes with zero errors; pnpm audit reports no known vulnerabilities in the dependency tree. A note on the contact form's key: Web3Forms designs its access key to be public, an alias for the destination inbox rather than a credential, and its free tier serves a Cloudflare challenge to any request whose TLS handshake is not a browser's. So the key ships in the client bundle as NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY and the browser performs delivery, but only after the server action has screened the submission: schema, honeypot and the per-IP rate limit all run server-side, and the browser delivers exactly what the action cleared. An earlier key appeared in the repository's git history and was rotated dead at Web3Forms.

Part X. Running the project

pnpm install
cp .env.example .env.local   # NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY, DATABASE_URL, GUESTBOOK_ADMIN_KEY: all optional locally
pnpm dev                     # http://localhost:3000
pnpm typecheck && pnpm lint  # checks
pnpm build && pnpm start     # production

Without the env vars the site runs fully; the contact form reports itself unavailable and the guestbook uses its in-process fallback.

Part XI. A worked example: signing the guestbook

  1. Double-click Guestbook. page.tsx adds "guestbook" to openWindows; window.tsx renders the frame at 600x640 and mounts window-content/guestbook.tsx.
  2. You type a name and message and draw something on the canvas. Submitting calls the server action with the fields plus the canvas as a data URL.
  3. The action checks the honeypot is empty, zod checks lengths, the rate limiter checks your IP has not signed in the last window.
  4. lib/guestbook.ts ensures the table exists (a cached promise guards the DDL) and inserts the row over the pooled connection.
  5. The window re-reads the list and your entry renders, drawing included. On a machine with no DATABASE_URL the same flow lands in the in-process list and the window says entries are temporary.

Part XII. Limitations and future improvements

  • Display settings, the guestbook, high scores, files written to the virtual drive and created desktop items persist; open windows and their layout still reset on reload.
  • Internet Explorer carries built-in pages only, since external sites refuse framing.
  • The Playwright checks that verify behaviour live in tests/checks/ and run with pnpm checks against a server on port 3000. They run on demand only; there is no hosted CI, so nothing runs them automatically on push.
  • Most valuable next: a Briefcase that really syncs two folders, Notepad's Find and Replace, and splitting Minesweeper's best times by board size.

Part XIII. Troubleshooting

SymptomCause and fix
"The guestbook is running without a database" DATABASE_URL is unset or unreachable. Set the pooled connection string and restart.
Contact form says delivery is unavailable NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY is unset.
No sound until you click Browsers block audio before a user gesture. The startup chime arms itself and fires on your first click or keypress. This is expected.
MIME type errors and a broken page in dev A production build overwrote .next under a running dev server. Stop the server, delete .next, run pnpm dev.
Port 3000 already in use A previous server still holds it. On Windows: Get-NetTCPConnection -LocalPort 3000 then stop the process.
Guestbook rejects a second entry The rate limit working as intended. Wait out the window.

Part XIV. Glossary

Bevel
The two-tone edge that makes Win95 controls look raised or pressed.
Canvas
A pixel drawing surface scripted from JavaScript.
Cascade
A submenu that opens beside its parent menu item.
CC0
A licence that places work in the public domain; the battle sprites use it.
Custom event
A named DOM message any component can dispatch or listen for.
Honeypot
A hidden form field only robots fill in; entries with it filled are dropped.
LCG
Linear congruential generator, the tiny random number recipe behind FreeCell's numbered deals.
localStorage
The browser's per-site key-value store, which is what makes saved files, drawings and scores survive a reload.
Marquee selection
The dotted rectangle drawn while dragging over the desktop.
Pooled connection
A shared database connection endpoint that survives many short-lived serverless instances.
Rate limit
A cap on how often one client may perform an action.
Server action
Next.js server function callable from the page.
Webamp
The open-source reimplementation of Winamp 2.9 used for the Winamp window.
Zod
A schema library that validates input shapes at runtime.
Zoom (CSS)
A style that scales an element and its layout, used to simulate resolutions.

Part XV. Learning path

Read in this order: app/page.tsx (the spine), then components/window.tsx, desktop.tsx and taskbar.tsx (the shell), then one simple program (window-content/notepad.tsx), one hard one (window-content/resume.tsx), one game (games/minesweeper.tsx), then the shared libs (lib/sound.ts, lib/guestbook.ts).

Afterwards you should be able to answer: where does the list of open windows live? How does a program ask the shell to open another program? Why is there no audio file in the repository? What stops the guestbook being spammed? Why does the calculator have no maximise button, and how does it resize its own window? What makes FreeCell's deal numbers match the original's?
